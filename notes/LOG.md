## 2026-11-10: Day-1 go/no-go (`kaggle/day1`, Kaggle v2)
- **Config:** Tiny Aya Global in FP16 on a T4.
  - A: 50 harmful and 50 harmless prompts, refusal measured by keyword match.
  - B: LoRA r=16 (q, k, v, o), batch size 4, sequence length 768, 100 steps.
  - C: Heretic with classic abliteration, 40 trials (12 random).
- **Pass criteria:**
  - Heretic cuts the harmful-prompt refusal rate sharply at low KL.
  - A LoRA step takes under ~3 s, so 1,000 steps finish in under 1 hour.
  - No NaN or garbage output in FP16.
- **Runs v2–v3:** failed because the CLI push didn't get the HF_TOKEN secret. Fixed by saving the version once in the UI (v4).
- **v4 result (T4):**
  - Check A passed: FP16 is fine (0 garbage outputs), refusal is 98% on harmful prompts and 0% on harmless ones, and generation runs at 110 tokens/sec (batch 8).
  - Check B crashed: Kaggle's torchao 0.10 is incompatible with peft. Fix: `pip uninstall torchao`.
  - Check C never ran.
- **Decision:** fold Checks B and C into the Day-2 job, to save quota and wall-clock time.

## 2026-11-11: Day-2 combined job (`kaggle/day2`, pushed to the same notebook as v5)
- **Order:**
  1. Heretic on the original model (abliteration, 40 trials). Runs first so the baseline survives later crashes.
  2. Data: 1,200 extended refusals generated by Tiny Aya (system-prompted, prompts from LLM-LAT/harmful-dataset, with Heretic's evaluation prompts excluded) plus 1,200 Dolly-15k benign answers distilled from the model itself.
  3. LoRA r=32 on all linear layers, 2 epochs, lr 1e-4, merged into v1. Weights go to a private HF repo; the dataset goes to a private HF dataset.
  4. Evaluation: refusal on harmful_behaviors test[:100] and over-refusal on XSTest safe prompts, for both the original model and v1.
  5. Heretic on v1, same configuration as step 1 (adaptive).
- **v5 result:** failed after 2 minutes with "no HF_TOKEN". **Confirmed: Kaggle does not pass secrets to versions pushed from the CLI**, even when the secret is attached to the notebook. No GPU time was used.
- **Next:** the user clicks Save Version → Save & Run All in the UI. The editor already holds the v5 code.
